## Warum jetzt

Apples Prüfer sitzt nicht in unserem WLAN. Heute läuft `server.js` auf Hannis
oder Antons Mac unter `http://192.168…` — für die Prüfung, TestFlight mit
Freunden und später echte Nutzer braucht es eine öffentliche, dauerhaft
erreichbare Adresse mit HTTPS: `https://api.dreamrushes.app`.

## Was der Server braucht (aus dem Code, 24.09.)

| Anforderung | Warum | Wo |
|---|---|---|
| **Bun** als Laufzeit | `Bun.serve`, `Bun.spawnSync`, Bun.SQL — kein Node | `server.js` |
| **Lange Verbindungen** bis ~255 s | Film/Analyse brauchen Minuten; `idleTimeout: 255`, Aufrufe darunter bis 300 s im Client | `server.js:2264`, `src/lib/api.js` |
| **WebSocket** | Sprachinterview: der Server reicht die Live-Verbindung zu Gemini durch | `server.js:2273`, `:2397` |
| **ffmpeg** | Abspann beim Teilen, Standbild aus dem Film, Audio nach mp3 | `server.js:1797`, `:1821` |
| **Genau EIN Prozess** | Mengenbremse zählt im Arbeitsspeicher; zwei Instanzen hätten zwei Zähler | `src/lib/gatekeeper.js` |
| **Dauerhafter Speicher** | Filme, Bilder, Sprachaufnahmen liegen heute als Dateien in `media/` (Stand: 15 MB, wächst mit jedem Film) | `src/lib/mediaRoot.js` |
| **Geheimnisse** nur auf dem Server | `FAL_KEY`, `DEEPSEEK_KEY`, `GEMINI_KEY`, `DATABASE_URL`, `SUPABASE_*`, `APPLE_*`, `API_TOKEN` | `.env.example` |
| **EU-Standort** | DSGVO; Supabase liegt in Frankfurt — nah dran = schnelle Datenbank | ADR-0005 |
| **IPv6** | Apples Prüfnetz ist teils nur IPv6 | App Review |
| **HTTPS** mit eigenem Zertifikat | `.app` erzwingt HTTPS; Apple ATS | — |
| **Echte Absender-IP** | Mengenbremse zählt je Absender — hinter einem Proxy muss die echte IP ankommen (S5) | `docs/ARCHITEKTUR.md` |

**Daraus folgt:** „Serverlos" (Supabase Edge Functions, Vercel, Netlify,
Cloudflare Workers) scheidet aus — zu kurze Laufzeiten, kein ffmpeg, keine
Dateien, keine gemeinsame Mengenbremse. Das stand schon in
`docs/ARCHITEKTUR.md` §6.

## Die Optionen

### A — Eigener kleiner Server (VPS) bei einem EU-Anbieter
Ein virtueller Linux-Server, darauf Bun, ffmpeg, **Caddy** (holt das
HTTPS-Zertifikat selbst, reicht WebSocket durch), `server.js` als Dienst.
- **Anbieter-Beispiele:** Hetzner (DE, Rechenzentren Nürnberg/Falkenstein),
  Strato (DE — Hanni hat dort schon ein Konto), netcup (DE), IONOS (DE).
- ➕ Erfüllt alles oben ohne Kompromiss; günstig; deutscher Vertrag; volle
  Kontrolle; ffmpeg und Dateien kein Thema.
- ➖ **Jemand muss ihn pflegen:** Sicherheits-Updates, Neustart nach
  Absturz, Backups, Überwachung. Das ist die eigentliche Frage an euch.

### B — Container-Plattform mit EU-Region
Man gibt ein Docker-Image ab, die Plattform betreibt es.
- **Beispiele:** Fly.io (Region Frankfurt), Render (Frankfurt), Koyeb (FR),
  Scaleway (FR), Railway.
- ➕ Weniger Pflege, Deploy per Git, Neustart automatisch.
- ➖ Meist US-Firmen (auch mit EU-Region gilt US-Recht für den Anbieter —
  Frage an den Anwalt); je Anbieter eigene Grenzen bei Laufzeit, WebSocket
  und dauerhaftem Speicher, die man einzeln prüfen muss; teurer; ein
  zusätzliches Konto mit Zugriff auf alle Schlüssel.

### C — Antons Rechner mit Tunnel
- ➕ kostet nichts.
- ➖ Fällt aus, wenn der Rechner schläft oder umzieht; Heimnetz-IP;
  **für Prüfung und echte Nutzer ungeeignet.** Höchstens für TestFlight im
  kleinen Kreis, übergangsweise.

## Empfehlung

**A — ein kleiner VPS bei einem deutschen Anbieter, in Deutschland**,
möglichst nah an Frankfurt (Supabase). Erfüllt jede Anforderung ohne
Umbau, ist am günstigsten und passt zu eurer EU-/Datenschutz-Linie.

Zwischen Hetzner und Strato: beides deutsch. Hetzner ist unter
Entwicklern verbreitet (Snapshots, IPv6 von Haus aus, Firewall im
Dashboard, gute Doku); Strato hätte den Vorteil, dass Domain und Server
beim selben Konto liegen. **Vor der Wahl bei beiden prüfen:** IPv6
inklusive? Snapshots/Backups? Firewall? Standort wählbar?

Die Pflege lässt sich klein halten — das bauen Claude-Sitzungen einmal:
- Automatische Sicherheits-Updates des Betriebssystems.
- `server.js` als systemd-Dienst: startet nach Absturz und Neustart selbst.
- Caddy davor: HTTPS, Zertifikat erneuert sich selbst, echte Absender-IP.
- Deploy als ein Befehl (Git holen, Abhängigkeiten, Neustart).
- Tägliche Snapshots beim Anbieter.
- Ein Erreichbarkeits-Check von außen, der Bescheid gibt.

## Medien: nach Supabase Storage, nicht auf den VPS (Hanni, 24.09.)

Filme, Bilder und Sprachaufnahmen sollen in **Supabase Storage** liegen
(Frankfurt, privater Bucket, je Konto ein Ordner, kurzlebige signierte
Adressen) statt in `media/` auf dem Server. Folgen:
- Der VPS braucht nur **vorübergehenden** Platz (ffmpeg) und keine
  Medien-Backups — er wird austauschbar. Das macht Option A noch kleiner.
- Löst N9/S2 (Zugangsschutz) und B8 (beim Konto-Löschen mitlöschen — ⚠ muss
  ausdrücklich passieren, die Datenbank-Kaskade erfasst Storage nicht).
- **Least Privilege:** Hochladen mit dem Token des Nutzers + Storage-Regeln
  „nur eigener Ordner", NICHT mit dem `service_role`-Schlüssel.
- ⚠ **Supabase Free reicht für den Betrieb nicht** (pausiert nach ~1 Woche
  ohne Zugriff, erlebt 22.09.) → bezahlter Tarif; Speicher- und
  Datenverkehrsgrenzen vor der Entscheidung auf der Preisseite prüfen.
- Umbau `server.js` (Medienablage, nicht Prompt-Kette) + App (Adresse beim
  Anzeigen frisch holen) + Umzug der vorhandenen Dateien: eigene Sitzung.
  Aufteilung von `server.js` mit Anton klären.

**Hannis Favorit (24.09.): zuerst Supabase Storage, Code von Anfang an

## Was vor echten Nutzern dazugehört (nicht vor TestFlight)

1. **Medien hinter Zugangsprüfung (N9/S2):** Heute bekommt jeder, der eine
   `/media/…`-Adresse kennt, die Datei — öffentlich gehostet geht das nicht
   (Gesichter realer Menschen). Weg laut `ARCHITEKTUR.md`: Supabase Storage
   mit kurzlebigen, signierten Adressen. Löst zugleich B8 (Medien beim
   Konto-Löschen mitlöschen).
2. **CORS-Testeintrag `"null"` raus / `API_TOKEN`** (Preflight B3a).
3. **App-Adresse** `EXPO_PUBLIC_API_BASE=https://api.dreamrushes.app`
   (Preflight B3b).
4. **Hosting-Anbieter in die Datenschutzerklärung** (Anwalt).

## Fragen an euch (Hanni + Anton)

   Filmen wird größer gebraucht — skaliert per Klick.
3. **Hetzner oder Strato** (oder anderer DE-Anbieter)?
4. **Wann:** Für TestFlight mit Freunden reicht der Server ohne Punkt 1
   oben; für die Einreichung muss N9 erledigt sein.
